# 活动效果评估模型

## 一、模型概述

用于评估游戏内活动（促活、版本、付费等）上线后的实际效果。从触达到参与、从参与到增量、从增量到成本效率，层层递进回答三个核心问题：

1. **用户有没有来？** → 触达度 + 参与度
2. **来了之后行为改变了吗？** → 参与深度 + 增量效果
3. **投入值不值？** → 成本效率

---

| 维度 | 指标 | 说明 |

| **元信息** | 活动名称 | — |

## 三、指标定义与取数逻辑

### 3.1 元信息（运营填写）

| 字段 | 来源 | 说明 |
|------|------|------|
| 活动名称 | 运营提供 | — |
| 活动机制 | 运营提供 | 每日任务 / 累计登录 / 限时挑战 / 抽奖 / 消费返利 等 |
| 时间点 | 运营提供 | 活动开始日期 |
| 天数 | 运营提供 | 活动持续天数（含开始和结束日） |
| 目标群体 | 运营提供 | 如"全服活跃玩家"、"7日内登录玩家"，需附人数 |
| 成本 | 运营提供 | 活动投入的总虚拟经济成本（道具价值折算） |

### 3.2 触达度

**触达率** = 活动入口曝光UV / 目标群体人数

- 数据来源：`client_obj_click`（活动入口按钮曝光/点击埋点）
- 曝光定义：活动入口出现在玩家屏幕上即算曝光（取曝光埋点，非点击）
- 若无独立曝光埋点，可用活动入口点击UV近似（但会低估）

### 3.3 参与度

**参与率（对触达）** = 参与UV / 触达UV

**参与率（对目标群体）** = 参与UV / 目标群体人数

- 参与定义：完成活动中至少 1 个任务/动作的玩家
- 数据来源：活动参与埋点或活动奖励领取埋点

**日均参与人数** = 活动期间每天参与UV之和 / 活动天数

- 注意：同一玩家多日参与，每天算一次
- 反映活动日常热度

**人均参与天数** = sum(每个参与者的参与天数) / 参与UV

- 反映参与粘性：人均参与天数 / 活动天数 → 参与频率

### 3.4 参与深度

**完成率** = 完成全部活动任务的UV / 参与UV

- 数据来源：活动完成/结算埋点
- "完成"定义视活动而定：如领取终极奖励、达到最终阶段等

**人均完成进度** = avg(每人的任务完成进度百分比)

- **未完成的玩家也纳入计算**（进度为实际达到的百分比）
- 示例：活动共 10 个任务，某玩家完成 6 个 → 进度 60%
- 目的：区分"很多人参与但都浅尝辄止" vs "参与者大多深入"

### 3.5 增量效果

> 增量效果是模型的核心。核心思想：**有对比才有结论**。

#### 参与前后时长对比

参与者的时长变化 = 活动期间日均游戏时长 / 活动前 7 天日均游戏时长

- 数据来源：结算日志 union（`unet_player_log` + `unet_golddash_player_log` + `unet_team_match_log`）
- "活动前 7 天"：活动开始日 T-7 至 T-1
- 仅看参与者自身前后变化，用于初步判断活动对行为的影响

#### 参与 vs 未参与时长对比（DID 净效应）

```
DID = (参与者活动中时长 - 参与者活动前时长) - (未参与者活动中时长 - 未参与者活动前时长)
```

- 参与组：活动期间参与了活动的玩家
- 对照组：同目标群体中未参与活动的玩家
- 排除自选择偏差：参与者本来就更活跃，前后对比会高估效果
- DID > 0 → 活动确实提升了参与者的游戏时长
- DID ≈ 0 → 参与者时长上升可能只是自身活跃度高，非活动所致

#### 活动后留存 (T+3/T+7)

- 活动结束日为 T，统计 T+3 和 T+7 当天参与者的登录率
- 数据来源：`gameserver_login`（`login_type = 0`）
- 目的：评估活动是否改变了玩家的长期行为

#### 留存端

留存端 = 参与者 T+7 留存 - 未参与者 T+7 留存（同期对照组）

- 正值 → 活动参与者留存高于自然留存，活动有正向长尾效应
- 零/负值 → 活动仅短期刺激，无长尾效应

### 3.6 成本效率

**单人参与成本** = 活动总成本 / 参与UV

- 成本由运营手动提供
- 成本口径：活动发放的虚拟道具/货币的折算价值

**单增量活跃天成本** = 活动总成本 / 增量活跃天总数

- 增量活跃天 = sum(每个参与者在活动期间多出的活跃天数)
- "多出的活跃天数" = 参与者活动期间活跃天数 - 按活动前频率预测的期望活跃天数
- 这是**最核心的 ROI 指标**：每增加一个活跃天，花了多少钱

## 四、数据收集后的评估工作流

```
取数 → 清洗 → 填表 → 横向对比 → 因果验证 → 结论输出
```

### Step 1：取数

由 DS Agent 按指标定义从 ClickHouse 拉取原始数据，需要的数据集：

| 数据集 | 内容 | 时间范围 |
|--------|------|---------|
| 活动参与日志 | 参与UV、每人每天是否参与、完成进度 | 活动期间 |
| 活动曝光日志 | 曝光UV | 活动期间 |
| 游戏时长日志 | 每人每天总游戏时长（union 各结算表） | T-7 至 T+7 |
| 登录日志 | 每人每天是否登录 | T-7 至 T+7 |
| 目标群体名单 | 符合活动目标条件的玩家 pid 列表 | T-1 快照 |

### Step 2：数据清洗

1. **排除不完整数据** — 当天未结束的数据不参与计算
2. **确认活动时间窗口** — 与运营确认实际上线/下线时间，精确到天
3. **定义对照组** — 从目标群体中排除参与者，剩余为对照组
4. **活跃度基线校验** — 检查对照组活动前活跃度是否与参与组可比（若差异过大需匹配处理）

### Step 3：指标计算（填表）

逐活动计算 18 个指标，填入评估总表。

计算顺序：
1. 元信息 → 直接填写
2. 触达率 → 曝光UV / 目标群体
3. 参与度指标 → 参与UV 为基础
4. 参与深度指标 → 完成率、进度
5. 增量效果 → 前后对比、DID、留存
6. 成本效率 → 成本 / 参与UV、成本 / 增量活跃天

### Step 4：横向对比

跨活动对比同维度指标，目标是回答：

- **哪种活动机制参与率最高？** — 按机制分组（每日任务/累计登录/限时挑战），对比参与率
- **哪种机制增量效果最好？** — 对比 DID 净效应和留存端
- **哪种机制性价比最高？** — 对比单增量活跃天成本
- **参与深度和增量效果是否正相关？** — 完成率高的活动，DID 是否也大

### Step 5：因果验证

对增量效果层的指标做 DID 验证，输出 DID 标准表格：

| | 活动前（T-7~T-1） | 活动中 | 差值 | DID |
|---|---|---|---|---|
| 参与组（日均时长） | A | B | B-A | (B-A)-(D-C) |
| 对照组（日均时长） | C | D | D-C | — |

- 遵循 DA 方法论：DID 表格直接展示原始数值，从原值推导到结论
- 如 DID 显著 > 0 → 活动有因果效果
- 如 DID ≈ 0 → 活动效果存疑，参与者本身就更活跃

### Step 6：结论输出

每个活动产出：

1. **一行总表数据** — 填入评估指标总表
2. **效果定档** — 超预期 / 符合预期 / 不及预期
3. **一段结论文字**：

> [活动名]（[机制类型]，[天数]天）触达率 X%，参与率 Y%，人均参与 Z 天。参与者日均时长提升 W%（DID 净效应 +M 分钟），T+7 留存端 +N pp。单增量活跃天成本 ¥P。效果定档：符合预期。

跨活动汇总产出：

> 本批 K 个活动中，[机制A]类活动在参与率和增量效果上表现最优（平均参与率 X%，DID +Y 分钟），[机制B]类活动成本效率最高（单增量活跃天成本 ¥Z）。建议后续活动优先考虑 [机制A] 框架。

## 五、对照组设计

增量效果评估的核心难点是**参与者自选择偏差**：主动参与活动的玩家本来就更活跃，直接对比参与者前后变化会高估活动效果。

### 方案 A：同群体未参与者对照

- 对照组 = 目标群体中未参与活动的玩家
- 优点：同时期、同条件，排除时间趋势
- 风险：未参与者可能本身就不活跃，需检查活动前基线是否可比

### 方案 B：参与者自身纵向对比

- 对照 = 参与者自己的活动前行为
- 优点：控制了个体差异
- 风险：无法排除时间趋势（如版本更新导致全服活跃上升）

### 推荐：A + B 结合（DID）

DID 同时控制了个体差异和时间趋势，是最稳健的方案。

## 六、使用说明

### 何时使用本模型

- 活动结束后 7 天（等 T+7 留存数据回填完成）
- 每个季度回顾性横向对比所有活动效果

### 前置条件

1. 运营提供：活动元信息（名称、机制、时间、目标群体、成本）
2. 活动有参与埋点（至少能区分"参与了" vs "未参与"）
3. 活动有完成/进度埋点（否则参与深度维度留空）

### 与 CLAUDE.md 活动分析框架的关系

DA CLAUDE.md 中的"活动数据分析框架"提供了分析方法论（四层漏斗、时间线分析、同期群分析等），本模型是其**指标落地层**——把方法论转化为具体的可填写表格和计算公式。

分析时应结合使用：
- 本模型 → 指标计算和效果定档
- CLAUDE.md 框架 → 分析视角和报告结构
